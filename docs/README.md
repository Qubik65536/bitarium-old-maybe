## Where information belongs

| Record | Owns |
| --- | --- |
| Context | Purpose, requirements, and component boundaries |
| Status and decisions | Accepted choices, proposals, and unresolved decisions |
| Progress | Milestone/task state, evidence, blockers, and next action |
| Task guides | Procedure, concepts, acceptance checks, and task-specific results |
| Research | Sources, facts, alternatives, and recommendations |
| Experiments | Actual setup, execution, observations, and interpretation |

Link related records rather than maintaining competing copies of the same decision or backlog.

## Reading the visual markers

Badges are local documentation labels, not live build or proof results. Written status fields and linked evidence remain authoritative. Update a badge when its meaning changes; never infer success from a guide being available.

Use section headings for navigation, tables for comparisons, checklists for observable acceptance checks, and Mermaid for relationships or branching behavior. Keep examples and commands close to the explanations needed to use them.
