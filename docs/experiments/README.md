**Make an observation reproducible and state exactly what it establishes.**

[Documentation](../README.md) · [Progress](../progress.md) · [Record template](TEMPLATE.md)

## Capture one question

Start with a small hypothesis or behavior: a boundary access, an instruction trace, an interoperation check, or a proof-tool trial. Record the expected result before the experiment and the actual outcome afterward.

| Include | Why it matters |
| --- | --- |
| Host, tools, and source revision | Identifies the environment tested |
| Inputs, commands, and limits | Makes the procedure reproducible |
| Actual output or state | Separates observation from prediction |
| Evidence source | Distinguishes directly observed and reported results |
| Interpretation and exclusions | Prevents a narrow result becoming a broad claim |

## Connect the result

Link the record from its task and milestone. Record failures and incomplete attempts as well as successes. For proofs, also follow the [verification plan](../verification.md) so assumptions and implementation coverage remain explicit.
